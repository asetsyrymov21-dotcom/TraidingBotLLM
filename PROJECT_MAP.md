## Корневые файлы

### `config.py`
Все настройки системы в одном месте. Содержит датаклассы:
- `MarketAnalyzerConfig` — параметры EMA, ADX, ATR (периоды, пороги тренда/флэта)
- `GridConfig` — кол-во уровней сетки, ATR-множитель, % депозита
- `TrendBotConfig` — TP/SL, динамика позиции, серии побед/убытков, анти-сквиз
- `EntryBotConfig` — RSI/MACD/BB периоды, TP/SL для умного входа
- `RiskConfig` — дневной лимит убытков, макс просадка, комиссия биржи
- `SystemConfig` — объединяет все конфиги выше
- `UserProfile` — профиль одного пользователя (API-ключи, биржа, плечо, %)

**Что менять здесь:** любые параметры торговли, риска, индикаторов.

---

### `exchange.py`
Универсальный коннектор к бирже через библиотеку CCXT.
- Поддерживает **Binance Futures** и **Bybit Linear**
- Методы: `fetch_ohlcv`, `fetch_ticker`, `fetch_balance`, `fetch_positions`
- Ордера: `place_market_order`, `place_limit_order`, `cancel_order`, `cancel_all_orders`
- Позиции: `close_all_positions`
- Утилита: `calc_position_size` — считает кол-во контрактов по % баланса
- Автоматически устанавливает плечо при старте
- Retry-логика при сетевых ошибках (3 попытки)

**Что менять здесь:** добавить новую биржу → добавить `elif name == "новая_биржа"`.

---

### `market_analyzer.py`
**Ядро системы.** Анализирует OHLCV-данные и определяет состояние рынка.

Индикаторы (реализованы с нуля на NumPy, без зависимостей):
- `EMA(50)` и `EMA(200)` — направление тренда
- `ADX(14)` — сила тренда (>25 = тренд, <20 = флэт)
- `ATR(14)` — волатильность, используется везде для динамических расчётов
- `RSI(14)` — моментум
- `MACD(12,26,9)` — импульс
- `Bollinger Bands(20,2)` — уровни отката

Возвращает `MarketSnapshot` — полный срез состояния рынка для всех стратегий.

Состояния рынка (`MarketState`): `TREND_UP`, `TREND_DOWN`, `FLAT`, `UNKNOWN`

**Что менять здесь:** пороги ADX, периоды EMA — в `config.py → MarketAnalyzerConfig`.

---

### `risk_manager.py`
Глобальный риск-менеджер. Защищает депозит пользователя.

- Проверяет дневной лимит убытков (по умолчанию 5%)
- Проверяет максимальную просадку (по умолчанию 15%)
- При превышении лимита → блокирует торговлю до следующего дня
- Регистрирует каждую сделку: считает gross PnL, комиссию биржи, **комиссию системы**
- Сбрасывает дневную статистику автоматически при смене даты
- Методы: `check_can_trade`, `register_trade`, `get_session_stats`, `get_commission_report`

**Монетизация:** `register_trade` автоматически вычитает комиссию системы (20–40%) из прибыли.

---

### `user_manager.py`
Мультипользовательская система. Управляет всеми подключёнными пользователями.

- CRUD: `add_user`, `remove_user`, `get_user`, `list_users`, `update_user_settings`
- Сохраняет пользователей в `data/users.json`
- Загружает при старте автоматически
- Поддерживает `custom_config` — индивидуальные переопределения параметров (TP, SL, %)
- `print_summary()` — консольная таблица всех пользователей

**Что менять здесь:** в production заменить хранение ключей на зашифрованное (AES/Vault).

---

### `bot_engine.py`
**Главный оркестратор.** Один движок на одного пользователя.

Логика каждого тика:
1. Загружает свечи с биржи
2. Анализирует рынок через `MarketAnalyzer`
3. Проверяет риск-лимиты через `RiskManager`
4. Если нужно — переключает стратегию (`grid` ↔ `trend`)
5. Запускает тик активной стратегии
6. При достижении риск-лимитов → экстренное закрытие всего

Режимы: `"grid"` (флэт) и `"trend"` (тренд, одновременно TrendBot + EntryBot).

**Что менять здесь:** логику переключения стратегий → метод `_determine_mode`.

### `main.py`
Точка входа. Два режима запуска:

```bash
python main.py        # боевой/тестнет запуск
python main.py demo   # демо без биржи (синтетические данные)
```

Класс `MultiUserRunner`:
- Запускает каждого пользователя и управляет тиками
- Graceful shutdown по Ctrl+C (SIGINT/SIGTERM)
- Логирует результаты каждого тика

**Что менять здесь:** интервал тика (`interval_seconds`), API-ключи или загрузку из `.env`.

Скрипт для первоначальной настройки пользователей.
Запускается один раз для добавления пользователей в `data/users.json`.

```bash
python setup_users.py
```

### `telegram_notifier.py`
Telegram-уведомления о действиях бота. Отправляет понятные сообщения на русском:
- Старт/стоп бота, итоговая статистика
- Открытие/закрытие позиций с объяснением ПОЧЕМУ
- Смена режима (GRID ↔ ТРЕНД) с объяснением причины
- Риск-блокировка, экстренное закрытие
- GRID: активация сетки, исполнение ордеров, выход из диапазона
- Периодический тик-саммари

Использует urllib (без зависимостей). Отправка асинхронная через threading.
Настройка: `TG_BOT_TOKEN` и `TG_CHAT_ID` через env-переменные или `config.py → TelegramConfig`.

## Стратегии (`strategies/`)

### `strategies/grid_strategy.py`
GRID-стратегия для флэтового рынка.

- При входе в флэт: строит сетку лимитных ордеров вокруг текущей цены
- Шаг сетки = `ATR × atr_multiplier` (динамический)
- BUY ниже центра, SELL выше центра
- После исполнения BUY → автоматически ставит SELL на шаг выше (и наоборот)
- Если цена выходит за диапазон + буфер → закрывает всё и выходит
- Отслеживает realized PnL по каждому уровню

Состояние: `GridState` (active, range_high/low, levels, realized_pnl)

---

### `strategies/trend_strategy.py`
Трендовый бот с полным набором улучшений.

Логика входа:
- Только в направлении EMA50/200 (фильтр тренда)
- RSI > 50 → только LONG, RSI < 50 → только SHORT
- WIN → продолжаем в том же направлении
- LOSS → переворот (открываем в обратную сторону)

Улучшения:
1. Динамический размер позиции (серия WIN → x1.2, LOSS → x0.8)
2. Задержка 1 свечу после убытка
3. Пауза 20 минут после 3 убытков подряд
4. Анти-сквиз: резкое движение >2.5% против позиции → закрыть
5. Анти-сквиз: аномальная волатильность → не входить
6. TP=1.8%, SL=1.1%

---

### `strategies/entry_strategy.py`
Бот умного входа. Открывает позицию только при подтверждении всеми тремя индикаторами.

Правило 3/3 — все должны совпасть:
- **RSI(14):** >50 = LONG, <50 = SHORT
- **MACD:** пересечение или положение выше/ниже сигнала
- **Bollinger Bands:** цена в нижних 20% полосы = LONG, в верхних 20% = SHORT

При 3/3 → открывает позицию с TP=2%, SL=1%.
Логирует причину входа для прозрачности.
